# BHTTP/1 Client — Network Architecture Course Project

This repository contains the **Track 2 — Client** implementation for the Network Architecture course project:

**HTTP, in Binary · Two Tracks, One Protocol**

The client implements the client side of the BHTTP/1 protocol and communicates with a separate compatible server.

## Track 2 — Client

The client:

- opens a TCP connection to the server
- builds a binary REQUEST frame
- sends the request
- reads RESPONSE and DATA frames
- writes the response body to stdout
- supports `-v` hexadecimal frame dumping
- exits with a non-zero status for 4xx/5xx responses
- skips unknown frame types using their declared payload length
- verifies `Content-Length` when it is present

The client follows the protocol defined in `SPEC.md`.

## Track 1 — Server

The corresponding server is implemented separately by my teammate Kartik.

**Server repository:**

https://github.com/Kartik-Pettugani/Network_Architecture_Project

The client and server are separate implementations. Their only shared contract is the BHTTP/1 protocol specified in `SPEC.md`.

Both sides use the same protocol/common definitions so that binary frames generated by one implementation can be understood by the other.

## Protocol

BHTTP/1 is a binary application-layer protocol running directly over TCP.

The protocol uses:

- a fixed 9-byte frame header
- 24-bit payload length
- 8-bit frame type
- 8-bit flags
- 31-bit stream identifier with one reserved bit
- big-endian encoding
- UTF-8 strings
- indexed and literal header encoding
- persistent TCP connections
- forward-compatible unknown frame handling

The complete wire-level specification is in `SPEC.md`.
